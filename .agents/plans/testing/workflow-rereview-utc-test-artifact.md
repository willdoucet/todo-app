## Operational invariants
- `state/review-log.jsonl` gains lines only; no existing line changes in either repository.
- The four status words are unchanged; `stale` is never written to the log.
- Every rejection by `review-log` leaves the log byte-identical and exits non-zero.
- `--next`, `--dashboard` and the banner never disagree: all three read `gate_state`.
- The plain banner exits 0 and prints its full set of lines for any log content that
  `review_log_scan` accepts as readable.
- Nothing displayed is parsed: changing or removing any `concern` or `reason` changes no
  verdict and no `next`.
- No reachable state leaves `--next` naming a skill that refuses to run.
- The harness `Note:` line is always last.

## Log hygiene
- No new log files. `review-log` prints the stored entry as JSON on success and a JSON error on
  rejection, as today; a rejection message names the fix (the flag to pass, the review to run).
- `concern`, `rereview_note` and `reason` are operator- and agent-written free text: they must
  never be interpolated into output without the one-line flatten, and must never carry a secret
  (same rule as every committed file; see AGENTS.md Guardrails).
