## Affected Pages/Routes
- `/` (mealboard) — meal planner view with SwimlaneGrid (desktop ≥768px) and MobileDayView (<768px)

## Key Interactions to Verify

### Food-item meal card (restructured)
- Hover over a food-item card → bottom edge expands 48px over 180ms, two action buttons fade in
- Tab to a food-item card → action zone expands on focus-within (keyboard)
- Move mouse away → action zone retracts smoothly
- Click "Mark cooked" on a food-item → name strikes through, small ✓ appears, sage pulse animation
- Click "Delete" on a food-item with the backend returning undo metadata → card replaced by `UndoMealCard` (undo flow)
- Click "Delete" on a food-item when backend returns no undo metadata → card removed; no error surfaced
- Look at the "Sweet Potato" card (icon-overlap bug target) → icon is centered ABOVE the title; full text "Sweet Potato" readable
- View a food-item with a deliberately long name (e.g., "Roasted Brussels Sprouts with Maple Glaze and Pecan Crumble") → wraps to at most 2 lines, card doesn't push row taller than other cells' height budget

### Recipe meal card (TOUCHED by widened scope)
- Hover/focus → unchanged; all existing recipe-card behaviors still work
- Click "Mark cooked" → unchanged path (shared handler)
- Click "Delete" with undo metadata → undo flow still works
- Click on the recipe card body → opens recipe drawer (unchanged)
- Visually confirm recipe cards look identical to the version shipped this morning (commit `b87d5e1`)

### Error feedback (new, both variants)
- With network disabled in DevTools, click "Mark cooked" on any meal card → inline red text "Couldn't save — try again." appears below the buttons for 3 seconds, then disappears
- With network disabled, click "Delete" on any meal card → error text appears
- Click delete on a meal entry that was already deleted on another device (simulate via DevTools by intercepting the DELETE and responding 404) → error text reads "This meal was already deleted." instead of the generic message
- While the 3-second error window is running, move your mouse completely off the card (desktop) → error stays visible for the full 3 seconds (does NOT slide shut with the action zone)
- Click the failed action a second time, this time with network restored → success flow runs AND the stale error text disappears immediately (not after the 3s timer)
- Click the failed action a second time with network still down → 3-second timer resets; the newest error gets a full read

### Accessibility
- Tab to a meal card's action button → focus ring (terracotta outline) is visible on keyboard focus, NOT on mouse click
- Inspect action buttons in DevTools → outer `<button>` is 44×44 (`w-11 h-11`), visible circle is 24×24 (food-item) or 32×32 (recipe)
- Use a screen reader (VoiceOver) and trigger an error → "Couldn't save, try again" is announced politely (not interrupting)
- Toggle macOS Accessibility → Display → Reduce motion → hover/focus expand is instant, no transition
- Dark mode toggle → sage-600 / terracotta-600 swap to green-400 / red-400 on error text; contrast still readable

## Edge Cases
- Long food-item name truncates to 2 lines via `line-clamp-2`; card height budget fits in shared swimlane row (~120px)
- Food-item in cooked state: strikethrough + sage-50 background + inline ✓ mini-row
- Food-item with participants different from slot defaults: avatars render inline below name
- Mobile viewport (720px): action zone always visible (no hover needed); tap behavior for mark-cooked + delete
- Unmount a card while an error timer is running (scroll to next week, or delete via another flow) → no "state update on unmounted component" warning in the console

## Critical Paths
- **Mark cooked on food-item (happy path):** hover → click → PATCH succeeds → strikethrough + pulse
- **Delete food-item with undo (happy path):** hover → click → DELETE returns undo token → card replaced by UndoMealCard
- **Error recovery:** first click fails → error text appears → retry succeeds → error clears immediately
- **Recipe variant unaffected:** every recipe-card behavior that shipped in commit `b87d5e1` still works
- **Icon overlap bug fixed:** "Sweet Potato" (and any multi-word food item) renders the full name with no visual overlap
