## Affected Pages/Routes

### Backend
- `GET /healthz` — health endpoint, returns `200 {"status": "ok"}`. Production gate: must NOT include version, hostname, env, or DB-status info in body.
- `POST /plumbing-test` — sets `__Host-plumbing-refresh` cookie with HttpOnly, Secure, Path=/, NO Domain attr, SameSite=Lax (or =None if browser matrix forces). Returns `{"set": true, "probe": "<opaque-value>"}` and `Cache-Control: no-store`. Removed in M5 PR #2.
- `GET /plumbing-test/read` — echoes the `__Host-plumbing-refresh` cookie back as `{"value": "..."}` and returns `Cache-Control: no-store`. Removed in M5 PR #2.
- Plumbing probe value semantics — the probe is throwaway transport-verification state only, never real auth/session state, never persisted server-side, and safe to echo back only because it is not a credential.
- `_parse_cors_origins` (`backend/app/main.py:18-26`) — modified to fail-fast when `APP_ENV=production` AND `CORS_ALLOW_ORIGINS` is unset/empty. Raises `RuntimeError` at import time.

### Frontend
- `https://mealy.dev/` — PlumbingShell component after Cloudflare Access challenge. Rendered via the `VITE_M2_SHELL=true` env-gate in `App.jsx` (Eng review 2, issue 3). Loads without making API calls it can't satisfy. Renders a "Test plumbing" button.
- "Test plumbing" button — lives inside `frontend/src/PlumbingShell.jsx`. Calls `POST /plumbing-test` with `credentials: 'include'`, stores the returned `probe`, then `GET /plumbing-test/read` with `credentials: 'include'` and `cache: 'no-store'`. Reports success only when `read.value === post.probe` exactly; must surface mismatch / null / network failures explicitly.
- `App.jsx` env-gate — `VITE_M2_SHELL === 'true'` → PlumbingShell; else → existing Routes tree. Local dev (`VITE_M2_SHELL` unset) keeps the full app functional during M2-M5.

### Edge / Infrastructure
- `https://api.mealy.dev/healthz` — Cloudflare Access challenge first, then returns 200.
- `https://api.mealy.dev/plumbing-test` and `/plumbing-test/read` — Cloudflare Access **bypassed on those exact paths only** (intentional during M2-M5).
- `https://api.mealy.dev/auth/*` — Cloudflare rate-limit (10 req/min/IP). No /auth code exists yet; rate-limit lands ahead of M3.
- `https://mealy.dev/` and `/assets/*` — Vercel cache headers (`max-age=0, must-revalidate` on index.html; `max-age=31536000, immutable` on assets).

### Rate-limit smoke test
- Because `/auth/*` remains behind Cloudflare Access during M2-M5, first obtain a valid Access-authenticated path for `api.mealy.dev` (for example: export a fresh `CF_Authorization` cookie from a logged-in browser session, or use a short-lived Access service token if already configured).
- Cloudflare rule action should be `Block`, not `Managed Challenge`, because `/auth/*` becomes API/XHR traffic in M3/M4 and challenge pages are the wrong failure mode for clients.
- Run a 15-request burst against `POST /auth/login` (returns 404 from origin since route doesn't exist) **with that Access credential attached**:
  ```bash
  for i in {1..15}; do curl -s -o /dev/null -w "%{http_code}\n" \
    -X POST https://api.mealy.dev/auth/login \
    -H "Content-Type: application/json" \
    --cookie "CF_Authorization=<value>" \
    -d '{}'; done
  ```
- If curl shows only `302`/`403`, the request never cleared Access and the test is invalid.
- **Authoritative check** if curl shows only 404s: Cloudflare dashboard → Security → Events → filter Action=Block, Service=Rate limiting. The 15-req burst should appear as ≥1 logged event from the testing IP.

## Edge Cases

### `/healthz`
- Body shape drift: pytest test must assert `response.json() == {"status": "ok"}` (exact equality, not subset). Future edits adding hostname/version would fail this.
- HTTP status: must be 200, not 204 or anything else.

### `/plumbing-test` cookie attributes
- Cookie name must be exactly `__Host-plumbing-refresh` (case-sensitive). The `__Host-` prefix is browser-enforced and requires Path=/, no Domain attr, Secure.
- Pytest test must inspect the `Set-Cookie` response header and assert: `HttpOnly`, `Secure`, `Path=/`, no `Domain=`, chosen `SameSite=` value, and `Cache-Control: no-store`.
- Pytest test must also verify POST returns a non-empty `probe`, and GET `/plumbing-test/read` returns null without the cookie and the exact cookie value when present.
- If browser matrix forces SameSite=None, M3 plan needs Origin/Referer validation added to /auth/* (parent plan already specifies this fallback).

### CORS production fail-fast (issue 4)
- Pytest test must verify: setting `APP_ENV=production` + unsetting `CORS_ALLOW_ORIGINS` causes `_parse_cors_origins` to raise `RuntimeError`.
- Conversely: `APP_ENV=production` + `CORS_ALLOW_ORIGINS=https://mealy.dev` does NOT raise.
- Conversely: `APP_ENV=development` (or unset) + `CORS_ALLOW_ORIGINS` unset returns the localhost defaults (existing behavior preserved).

### `/plumbing-test` Cloudflare Access bypass
- Slice 5 verification must confirm the XHR never receives a 302 to `*.cloudflareaccess.com`. If it does, the bypass policy is missing or too broad / too narrow.

### Vercel cache headers
- `curl -I https://mealy.dev/` → `Cache-Control: public, max-age=0, must-revalidate`
- `curl -I https://mealy.dev/assets/<some-hashed-file>.js` → `Cache-Control: public, max-age=31536000, immutable`

### `migration-upgrade` CI job
- Job runs `alembic upgrade head` on a clean Postgres 16 container
- Then runs `alembic downgrade -1 && alembic upgrade +1` to verify newest revision's up/down symmetry
- Job appears in PR checks; must be green to merge

- `fly logs --vm <beat-vm-id>` must show at least one `Scheduler: Sending due task` line within 10 minutes of deploy (the iCloud sync schedule)
