## Affected Pages/Routes

- `/mealboard` (Meal Planner view — desktop, `md` breakpoint and above) — the only page where the fix applies. The mobile `MobileDayView` branch at `MealPlannerView.jsx:437-449` is unaffected (no hover state).

## Key Interactions to Verify

**On the Meal Planner page, current week, with "Blueberry Pancakes" (or any food-item) visible as a MealCard:**

1. **Pre-flight reproduction check.** In a browser with classic (non-overlay) scrollbars, confirm the bug reproduces BEFORE the fix is applied: hover the food-item card, observe title reflow to 2 lines AND horizontal shift of the day/date row + swimlanes. If unable to reproduce (e.g., macOS with default overlay scrollbars), switch System Settings → Appearance → "Show scroll bars" to "Always" before continuing.

2. **Hover stability (post-fix):** Hover a food-item MealCard. Verify:
   - Card's title text stays on 1 line before, during, and after hover.
   - Day/date header row ("Sun Mon Tue ... Sat") does not shift horizontally.
   - SwimlaneGrid container bounding-box width does not change.
   - Only the card's action zone (max-h: 0 → 48px) grows, and the swimlane expands to fit.

3. **Mouse exit:** Move mouse off the card. Verify the action zone retracts with no horizontal shift.

4. **Recipe variant parity:** Repeat interactions 2 and 3 on a recipe MealCard (e.g., any card with a recipe attached). Same stability expected.

5. **Reduced-motion parity:** Open DevTools → Rendering → Emulate CSS media → set `prefers-reduced-motion: reduce`. Re-run interactions 2 and 3. Hover-expand snaps instantly; stability invariants still hold.

6. **Already-overflowing week:** Populate (or visually simulate) a week with enough meals to force the scroll container to overflow at rest. Hover any MealCard. Verify no new jitter is introduced.

## Edge Cases

- **Short week (no overflow at rest):** Load a sparse week. Visually confirm the reserved scrollbar gutter (~15px empty stripe on the right) looks intentional, not broken.
- **Overlay-scrollbar environment:** On macOS with overlay scrollbars enabled (default trackpad setting), hover a card. Fix is a no-op here, which is correct (bug did not reproduce in this environment either).
- **Mobile / compact mode:** Narrow the browser below the `md` breakpoint (MobileDayView takes over). Hover-via-touch doesn't apply; verify no regression in the touch-driven mobile layout.
- **Long food-item name:** If a food item has a name that legitimately requires 2 lines (e.g., "Sweet Potato Hash Browns"), verify `line-clamp-2` still gracefully wraps it to 2 lines at rest — the fix is not about forcing 1-line titles, only about preventing hover-triggered width oscillation.

## Critical Paths

- **Golden path:** User lands on `/mealboard`, current week has at least one food-item card, user hovers over it, sees ONLY the card's bottom extend + action buttons fade in + swimlane grow. Nothing else moves.
- **Regression watch for prior mealboard work:** The `mealboard-meal-card-polish` PR (#22, just merged) designed the hover-expand animation — this fix patches its layout-ambient side effect. Verify the hover-expand animation itself (`max-h` + opacity + padding-bottom transition at 180ms) is unchanged in timing and visual appearance.
- **Scroll works:** On a busy week that legitimately overflows, verify the user can still scroll the mealboard container vertically (scrollbar functionality, not just gutter reservation).

## Not in scope (covered by follow-up P3 PR)

- Automated Playwright screenshot diff baselines for SwimlaneGrid / MealCard (recipe + food-item) / UndoMealCard / AddMealPopover.
- CI integration for visual regression.
- Fixed-font Docker image for deterministic rendering.

The hover-jitter invariants listed above (bbox.x of day headers, bbox.width of SwimlaneGrid) are the motivating test case for the follow-up PR and should be its first baseline captures.
