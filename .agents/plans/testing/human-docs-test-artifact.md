## Edge cases
- Interrupted ship, re-run the same UTC day with `gh` — lookup (a) finds the entry by `<PR_URL>)`; it is rewritten in place; no `-2` file appears; History keeps one row for it.
- Interrupted ship, re-run the next UTC day — the entry keeps yesterday's filename and `LOG_DATE`; the feature page's History row links that filename; the "As of" line carries today's date.
- Ship without `gh`, then a second run with `gh` — the first run writes `[PR pending](<compare URL>)` in both files and reports `DONE_WITH_CONCERNS`; the second run's lookup (b) finds the entry by `[PR pending]` and the branch name and replaces the PR cell with the real number.
- `PR_URL` empty at step 8 (simulate by unsetting it) — neither lookup runs; `PR_URL` falls back to the compare URL; both files carry `PR pending`; no other entry is rewritten (this was the clobber the review reproduced).
- Two `[PR pending]` entries for one branch on different dates, neither merged — lookup (b), and lookup (a) with the compare URL, both return the newest by filename (Eng review 2: `head -1` returned the older one).
- Part 2 of a plan on the same branch, part 1's `[PR pending]` entry already merged to the base branch — neither lookup returns it, with or without `gh`; part 2 gets a new entry (`-2` on the same UTC day) titled `(part <label>)`, and part 1's entry is byte-identical.
- Partial ship (`PARTIAL=1`) with a feature page — "What it does" describes only what works once this part merges, never the plan's end state; the History row's text carries `(part <label>)`.
- `ship-record` refused at step 8 (`RECORDED` empty) — both human-docs files are still written, without a part suffix; the ship's `DONE_WITH_CONCERNS` already names the refusal; a re-run's lookup (a) finds the entry and adds the suffix.
- No readable base ref (no `origin`, no local base branch) — every lookup hit passes the filter, as before Eng review 2; nothing errors.
- A log filename that exists and was not returned by (a) or (b) — the entry is written with the lowest free `-N` suffix (N ≥ 2), never over the existing file.
- `PR_URL` for `/pull/5` with an entry for `/pull/58` present — lookup (a) returns only the `/pull/5` entry (the `)` boundary).
- Existing feature page with a person's section added below `## History` — it survives the rewrite; the three owned sections and the "As of" line are replaced; a `## Custom` heading between owned sections survives; a `### ` sub-heading inside `## What it does` is replaced with it.
- Existing feature page with an anchor heading removed by a person — the page is refilled whole, unrecognized sections are carried below `## History`, and the transcript says so.
- History at ten rows — the next ship prepends one and drops the oldest; the log folder still holds every file.
- Log-only ship — no feature page is written or touched; the log entry's header says `log-only`; completion says `HUMAN DOCS: log-only: log/<file>`.
- `modules.human_docs: false` in a scratch repo — ship steps 1 and 8 print one skip line each; `upgrade` creates nothing under `docs/` and prints exactly one line containing `human docs off`; the exempt list is unchanged.
- `modules.human_docs: "false"` (a string) — the installer treats it as off and its skip line names the value.
- `"modules": []` in a scratch repo's config — `upgrade` exits 0, prints one `WARN` line containing `config shape`, writes nothing under `docs/`, still bumps `framework_version`.
- `docs/human/` deleted by hand while the flag is on — `doctor` warns; the next `upgrade` re-creates the folders; the next ship's step 8 `mkdir -p` succeeds without waiting for either.
- A consumer removed `docs/human/**` from `doc_map.exempt` — the record commit still passes (`unmapped area` note on stderr only); `doctor` warns.
- A consumer removed the `.obsidian/` line — `doctor` warns; the next `upgrade` re-adds it.
- Locally edited `.agents/templates/human/README.md` or `feature.md` — `upgrade` leaves them with the `modified locally` warning; a re-run of `upgrade` does not re-render `docs/human/README.md` because it exists.
- Consumer with an existing `docs/` directory — `docs/human/` nests inside it; nothing else under `docs/` is read or written.
- Empty `docs/human/log/` or missing `docs/human/features/` at step 1 — the listing is empty, no error; step 8 creates the folders.
- Brief path that does not exist — `NEEDS_CONTEXT` naming it; nothing written.
- Brief that is untracked and the plan is abandoned after approval — the file stays gone; `## Source brief` in the plan holds its text; the ABANDONED report says so.
- Brief that is tracked, with uncommitted edits, and the session is abandoned before approval — nothing is checked out; the edits survive.
- Branch name holding a regex metacharacter (`feat.x`) — lookup (b) may over-match a sibling entry only if that entry is also `[PR pending]` and shares the pattern; a benign duplicate at worst, visible in the PR diff.

## Operational invariants
- One log entry per pull request: after any number of `/ship` re-runs for one PR, `grep -rlF -- "<PR_URL>)" docs/human/log` returns exactly one file.
- A log entry the base branch already has is never modified by a later ship: `git diff --diff-filter=M origin/<base> -- docs/human/log/` is empty on every branch at its record commit (Eng review 2).
- `docs/human/briefs/` on the base branch equals what is still parked: no brief whose plan is approved survives a merged ship.
- Every feature page opens with `As of <utc-date> · [PR #n](…) · [plan](…)` and its History links only filenames that exist in `docs/human/log/`.
- No `.obsidian/` directory is ever tracked in the repository (`git ls-files | grep -cE '(^|/)\.obsidian/'` is 0; final review 2: the old `'/\.obsidian/'` missed a vault opened at the repository root).
- The framework suite stays green with `office-hours/SKILL.md` at exactly 500 lines; the count is asserted by `test_skill_conventions`.
- `.agents/docs/` and `.agents/plans/` are never written by the human-docs hook; the only plan edit at ship time is the frontmatter `plan-metadata-set` that already exists.
- The record commit passes `doc-guard --staged --dry-run` without a trailer in a consumer that carries the exempt glob.

## Log hygiene
- Ship step 8 prints the two file paths it wrote and their contents into the transcript before step 9; the `HUMAN DOCS:` completion line names them again.
- The installer prints one `done`/`plan` line per file or config change on the first run and nothing on a repeat; `--dry-run` prints `plan` in place of `done`.
- Doctor prints `WARN` lines only; never `FAIL` for a human-docs condition.
- Nothing secret can appear: the hook reads the plan, the summary, the PR body and the REVIEW REPORT, all committed text; `PR_URL` and the branch name are the only variables interpolated.
