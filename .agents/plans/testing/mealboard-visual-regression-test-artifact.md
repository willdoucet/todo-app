**NOTE:** This plan *is* test infrastructure. The "features" being tested are visual
invariants of the mealboard surface, run via Playwright in CI. Human QA at PR time is
minimal — the automated suite is the gate. This artifact lists what to verify
**about the infrastructure itself** after the plan ships.

## Affected Pages/Routes
- `/mealboard` at viewport 1440×900 (the only page the VRT suite currently exercises).

## Key Interactions to Verify (infrastructure-level)
- `docker-compose --profile visual-test up -d --wait db redis api-test frontend-preview` starts cleanly
  from a fresh `docker-compose down -v` on a machine that has the required `.env`.
- `docker-compose --profile visual-test run --rm frontend-visual` runs the four canonical
  specs + the new smoke spec (Issue 8A) and exits 0 with no flakes.
- CI PR check `visual-tests` shows up on an open PR and passes on the plan's own PR.
- On a deliberate geometric regression (revert the `mealboard-scroll-stable` class on
  `MealPlannerView.jsx:430`), the `swimlane-hover-jitter.spec.js` spec fails with a
  message containing `width stable on hover` (tightened per Issue 9A).
- HTML report at `frontend/test-results/report/index.html` opens and shows per-test
  failure details + trace.
- `playwright-report` artifact uploads on CI failure and is downloadable.

## Edge Cases
- **Dual-pin drift (Issue 1B):** Manually bump `@playwright/test` in `package.json` to a
  version that does NOT match the `PLAYWRIGHT_VERSION` ARG. Rebuild the image. The build
  must fail with a clear "playwright version mismatch" error (not a silent success).
- **Seed idempotency (Issue 2A):** Run the suite locally twice in a row without
  `docker-compose down -v` in between. Second run must produce identical test outcomes
  (no duplicate cards, no count drift).
- **Hung api-test (Issue 7A):** Manually `docker-compose pause api-test` mid-run. Seed
  must fail within 10s with a `SeedError: timeout after 10s` message, not hang until
  Playwright's 30s test timeout.
- **Smoke spec (Issue 8A):** Break the mealboard page intentionally (e.g., throw at the
  top of `MealPlannerView.jsx`). The suite must fail at `smoke.spec.js` first, not at
  four cryptic locator timeouts.
- **reducedMotion (Issue 4A):** Without `reducedMotion: 'reduce'` in the Playwright
  config, `settleTransitions`'s 300ms wait was the only thing preventing bbox flake. Verify
  that the new config disables animations app-wide: hovering a MealCard should jump
  instantly to the hovered state in the Playwright trace, not transition.
- **CORS env override (Eng review rerun R1):** With `CORS_ALLOW_ORIGINS` unset in the
  regular `api` service, `GET /items` from `http://localhost:5173` must still succeed
  (prod behavior unchanged). With `CORS_ALLOW_ORIGINS` set on `api-test`, a browser at
  `http://frontend-preview:4173` must reach `/items` and `/meal-entries` without a
  CORS error in the console. If this breaks, the whole visual-test suite dies on the
  smoke spec's `cardCount >= 3` and `consoleErrors === []` assertions.

## Critical Paths
- **Zero-flake soak (SC6):** 10 consecutive CI runs on an unchanged commit pass with zero
  retries. This is the gating check before flipping `visual-tests` to a required status.
- **Rollback (SC8):** If flake emerges post-merge, a one-line PR deleting the
  `visual-tests` job from `.github/workflows/test.yml` restores the pre-VRT state with
  no DB or feature-flag implications. Confirm by simulating once.
- **Branch-protection flip:** After SC6 passes, flip `visual-tests` to Required in
  GitHub Settings → Branches → main. The next PR with a geometric regression must fail
  to merge until green.

## What this artifact is NOT
- A checklist of manual clicks through the app — visual invariants are automated.
- A test plan for features in `/mealboard` — those are covered by their own unit tests
  (Vitest + RTL) and by the new Playwright bbox assertions written against them.
- A test plan for a user-facing feature — this work is CI infrastructure.
