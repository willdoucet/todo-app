## Problem Statement

Mealboard polish PRs keep landing the same class of bug: RTL unit tests assert class names pass, but the rendered surface still jitters, shifts, or collapses. Recent examples:

- Hover-expand animation in `mealboard-meal-card-polish` — RTL confirmed `max-h-[48px]` was applied, but couldn't confirm no-flicker animation, badge-vs-action-zone non-overlap, or absence of Safari clip-flicker.
- Hover-jitter fix just shipped (`mealboard-todos-042026-plan-20260420-185106`) — 15px column shift on hover, title wraps, swimlane geometry oscillates. RTL could not have caught this.
- Every mealboard polish PR logs "Open Question: visual regression coverage for this chunk" and defers to a future P3.

The deferred P3 is this plan. Today there is no automated gate that catches geometric drift between PR and main. We eyeball and ship; the next polish PR rediscovers the hole.

## What Makes This Cool

**The insight:** visual regression does not require pixel diffs for the bug class we actually hit. The bugs here are geometric — bbox position/size deltas across state transitions — not aesthetic (pixel color, exact glyph shape). Geometric invariant tests (`grid.boundingBox().width` stable across hover/rest/exit) are deterministic *without* font-rendering Docker wrestling, which is the conventional VRT flake source.

Geometric-first ships faster, eliminates the flake tax, and leaves a clean seam for a pixel-diff layer later when we want to guard aesthetic regressions (hover-fade opacity curve, shadow intensity, color palette). The "coolest version" is a small test architecture where adding a new invariant is a one-liner, and where the eventual 10x stretch — a PR bot that posts visual diffs as review comments — drops into the same fixture cleanly.

## Constraints

- **No Storybook.** Chromatic/Storybook-VRT is out — would be a large scope expansion to adopt Storybook for the mealboard surface alone.
- **Existing stack is fixed:** Vitest + RTL (unit), MSW (frontend mocks), docker-compose (dev + CI consistency per CLAUDE.md), GitHub Actions (CI), pytest + testcontainers (backend).
- **All commands must run through Docker Compose** per CLAUDE.md — no host-installed Playwright or Chromium.
- **Baselines live in-repo.** No third-party service (Chromatic, Percy, Applitools).
- **One-person project, low flake tolerance.** A single flaky visual test would erode trust in the suite and get disabled. Zero-flake is a hard bar, not a nice-to-have.
- **`[data-testid]` hooks are acceptable** but should be minimal — one attribute per stable target (MealCard variants, SwimlaneGrid, day-header cells, undo card).

## Premises (confirmed with user)

1. **Playwright, not Vitest + RTL.** RTL's JSDOM returns zero for every `boundingBox()` — geometric assertions require a real browser engine rendering real CSS.
2. **Tests hit the prod bundle via `vite preview`** (port 4173), not the dev server. Same bundle in local runs and CI — eliminates dev/prod drift at test time. `vite preview` is already scripted in `frontend/package.json:10`.
3. **Seeded database, not API mocks.** Leverages the existing `todo_app_test` database and integration-test pattern. Less fragile than mocking every fetch with MSW; accepts ~5-10s test startup cost.
4. **First-land deliverable = four canonical states + hover-jitter invariants + green CI, not a framework.** Scope discipline: concrete tests before general abstractions.
5. **Geometric-first does not preclude pixel later.** Architecture must leave a clean seam so `toHaveScreenshot()` assertions can be added alongside bbox assertions in the same spec, using the same fixture helpers, without rewriting.

## Approaches Considered

### Approach A: Minimal flat specs
Four spec files, each independently writing `hover()` → `boundingBox()` → `expect().toBe()` with no shared helpers.
- **Effort:** S (human: ~half day / CC: ~2h)
- **Pros:** Ships fastest. Boring. Zero abstraction.
- **Cons:** Adding test #5 repeats the hover/rest/exit dance. No seam for pixel-layer extension.

### Approach B: Geometric fixture [CHOSEN]
Four canonical-state specs + a `fixtures/geometric.js` helper that encapsulates hover/rest/exit transitions and common bbox assertions. New tests become one-liners.
- **Effort:** M (human: ~1 day / CC: ~3h)
- **Pros:** Test #5 costs ~15 min. Learning moment on test architecture. Clean seam for pixel layer and for the eventual PR-bot stretch.
- **Cons:** ~50 extra lines of fixture code to maintain.

### Approach C: Story-driven invariants
Organize tests by behavioral contract ("hovering doesn't shift the grid," "card expands by exactly 48px," etc.) instead of by UI state.
- **Effort:** M (human: ~1 day / CC: ~3h)
- **Pros:** Test names map to real bugs. Invariant-thinking muscle.
- **Cons:** Re-frames the TODOs.md "four canonical states" structure. Contract churn rewrites more tests.

## Recommended Approach: B — Geometric fixture

Four canonical-state spec files backed by a shared fixture. Matches the user-chosen shape (geometric-first, four canonical states, PR-bot as the 10x). Fixture pays back starting test #5 and leaves the cleanest seam for the pixel-diff layer.

**Frontend Dockerfile addition** (new `preview` target):

```dockerfile
FROM node:20-slim AS preview
WORKDIR /app
ARG VITE_API_BASE_URL=http://api-test:8000
ENV VITE_API_BASE_URL=${VITE_API_BASE_URL}
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build
EXPOSE 4173
CMD ["npx", "vite", "preview"]
```

**Why `VITE_API_BASE_URL` is a build ARG, not a runtime env var:** Vite bakes `import.meta.env.VITE_*` into the bundle at build time. The Playwright browser runs inside the `frontend-visual` container, not on the host — so `localhost:8000` from inside that container resolves to itself, not to the api. Building the bundle with the Docker service name (`http://api-test:8000`) is the only thing that works end-to-end.

**`vite.config.js` addition** — host/port/strictPort live here in the config file (single source of truth; Dockerfile CMD stays minimal):

```js
// ... existing config ...
preview: {
  allowedHosts: ['frontend-preview', 'localhost'],
  host: '0.0.0.0',
  port: 4173,
  strictPort: true,
},
```

Without `allowedHosts`, Vite 7 preview returns `403 Blocked request. This host is not allowed.` when the browser hits `http://frontend-preview:4173/`.

**`frontend/tests/visual/fixtures/geometric.js`** (Eng 4A + Eng 5A):

```js
import { expect } from '@playwright/test';

// Exported so specs can reuse them directly or reason about the defaults (Eng 5A).
export const PX_TOLERANCE = 0.5;        // Half-pixel tolerance for stable-across-state assertions
export const DELTA_TOLERANCE = 1;       // 1px tolerance for expected deltas (sub-pixel layout rounding)

export async function bboxOf(locator) {
  const box = await locator.boundingBox();
  if (!box) throw new Error(`boundingBox returned null for ${locator}`);
  return box;
}

// Eng 4A — with reducedMotion: 'reduce' in the Playwright config, hover transitions
// do not run (SwimlaneGrid.jsx:49 honors the media query). We only need to wait for
// fonts so text-sized bboxes stabilize. No more 300ms timeout flake vector.
async function settleTransitions(page) {
  await page.evaluate(() => document.fonts.ready);
}

export async function waitForMealboardReady(page, { targetCardName } = {}) {
  // Adversarial review A3: prefer explicit UI readiness over `networkidle`, which
  // is a transport heuristic and can hang or go green on the wrong state.
  await page.goto('/mealboard/planner');
  await expect(page.locator('[data-testid="swimlane-grid"]')).toBeVisible();
  if (targetCardName) {
    await expect(
      page.locator('[data-testid="meal-card"]').filter({ hasText: targetCardName }).first()
    ).toBeVisible();
  } else {
    await expect(page.locator('[data-testid="meal-card"]').first()).toBeVisible();
  }
  await page.evaluate(() => document.fonts.ready);
}

export async function expectStableAcrossHover(
  page,
  staticLocator,
  hoverTargetLocator,
  dims = ['x', 'y', 'width', 'height'],
  neutralLocator = null,
  { tolerance = PX_TOLERANCE } = {}   // Eng 5A — per-call override.
) {
  const rest = await bboxOf(staticLocator);
  await hoverTargetLocator.hover();
  await settleTransitions(page);
  const hovered = await bboxOf(staticLocator);
  if (neutralLocator) {
    await neutralLocator.hover();
  } else {
    await page.mouse.move(0, 0);
  }
  await settleTransitions(page);
  const exited = await bboxOf(staticLocator);
  for (const d of dims) {
    expect(Math.abs(hovered[d] - rest[d]), `${d} stable on hover (delta should be <${tolerance}px)`).toBeLessThanOrEqual(tolerance);
    expect(Math.abs(exited[d] - rest[d]), `${d} stable on exit (delta should be <${tolerance}px)`).toBeLessThanOrEqual(tolerance);
  }
}

export async function expectDeltaOnHover(
  page,
  targetLocator,
  dim,
  expectedDelta,
  neutralLocator = null,
  { tolerance = DELTA_TOLERANCE } = {}   // Eng 5A — per-call override.
) {
  const rest = await bboxOf(targetLocator);
  await targetLocator.hover();
  await settleTransitions(page);
  const hovered = await bboxOf(targetLocator);
  // toBeCloseTo(expected, 0) tolerates sub-pixel layout rounding up to 0.5; widen via `tolerance`
  // only if a spec has a documented reason. Default integer-pixel tolerance catches off-by-ones.
  expect(Math.abs(hovered[dim] - rest[dim] - expectedDelta)).toBeLessThanOrEqual(tolerance);
  // Restore to rest state so state does not leak into the next assertion.
  if (neutralLocator) {
    await neutralLocator.hover();
  } else {
    await page.mouse.move(0, 0);
  }
  await settleTransitions(page);
}
```

**`frontend/tests/visual/fixtures/global-setup.js`** (new, Eng 10):

```js
import { seedKnownWeek } from './seed.js';

export default async function globalSetup() {
  await seedKnownWeek();
}
```

Specs no longer declare a `beforeAll` for seeding — `globalSetup` runs once per job
before any spec starts. Specs only do per-test state manipulation (e.g. the undo
spec's soft-delete + `afterEach` restore).

**Tolerance rationale:** `boundingBox()` returns floats. Sub-pixel rounding from CSS transforms, viewport scaling, and browser layout reflow produces fractional deltas (e.g. `123.50000000000006` vs `123.5`) even when nothing semantically changed. Strict `toBe()` will flake. `PX_TOLERANCE=0.5` passes genuine stability, fails real shifts (the hover-jitter bug was 15px). For deltas, `toBeCloseTo(N, 0)` accepts `|actual - expected| < 0.5` — tight enough to catch a real off-by-one while tolerating sub-pixel layout rounding. If a real change in hover-expand delta (e.g. 48 → 52px) ever legitimately lands, the assertion breaks and the dev updates the constant.

**Example spec (`swimlane-hover-jitter.spec.js`)** — post-Eng 10 shape (no `beforeAll`; seed handled by globalSetup):

```js
import { test } from '@playwright/test';
import { expectStableAcrossHover, waitForMealboardReady } from '../fixtures/geometric.js';

test('SwimlaneGrid width + all day-header x-positions stable across MealCard hover', async ({ page }) => {
  await waitForMealboardReady(page, { targetCardName: 'VRT Food Item Alpha' }); // Adversarial review A3

  const firstCard = page.locator('[data-testid="meal-card"]').filter({ hasText: 'VRT Food Item Alpha' }).first();
  const grid = page.locator('[data-testid="swimlane-grid"]');
  const days = ['mon', 'tue', 'wed', 'thu', 'fri', 'sat', 'sun'];
  const weekHeader = page.locator('[data-testid="week-header"]');

  await expectStableAcrossHover(page, grid, firstCard, ['width'], weekHeader);

  for (const d of days) {
    const header = page.locator(`[data-testid="day-header-${d}"]`);
    await expectStableAcrossHover(page, header, firstCard, ['x'], weekHeader);
  }
});
```

**Seeding strategy** (Eng 2A + Eng 7A + Eng 10):

- `seed.js` talks to the current FastAPI routes (`/items`, `/meal-entries`) using `API_URL` — no `/api` prefix, and no legacy `/recipes` / `/food-items` endpoints (Adversarial review A1).
- A fixed "known week" = three LIVE canonical entries with unique, VRT-only names (for example `VRT Recipe Alpha`, `VRT Recipe Beta`, `VRT Food Item Alpha`) so specs can target them by text without relying on sort order (Adversarial review A3).
- **Idempotent** (Eng 2A): on entry, `seedKnownWeek()` first calls `GET /meal-entries?start_date=<known-monday>&end_date=<known-sunday>` and `DELETE`s any matching entries (signature = date range + slot-type combo), then re-inserts the canonical set. Local reruns stay clean without `docker-compose down -v`.
- `seedKnownWeek()` creates recipe + food-item records through `POST /items` with the real unified item payload shape (`item_type` + nested `recipe_detail` / `food_item_detail`) before creating the matching `POST /meal-entries` rows (Adversarial review A1).
- **Undo spec isolation** (Adversarial review A2): do NOT seed an already-soft-deleted row. `mealcard-undo.spec.js` creates a dedicated throwaway meal entry during the test, deletes it to observe the inline undo card, and restores or removes that throwaway row in `afterEach` / `finally` so a failed cleanup cannot contaminate the shared geometry fixtures.
- **Per-call timeout** (Eng 7A): every `fetch()` uses `AbortSignal.timeout(10_000)`. `AbortError` is re-thrown as `SeedError: timeout after 10s on <METHOD> <url>. Likely cause: api-test deadlocked or migration hang.` Matches the SeedError template from CEO 2A.
- **Runs via `globalSetup`** (Eng 10), not per-spec `beforeAll`. One seed per job, full stop.
- Teardown: the test runs against `todo_app_test` which is reset per CI run (initial schema from `alembic upgrade head`). Locally, the idempotent seed handles the rerun case; `docker-compose down -v` is still the nuclear reset when needed.
